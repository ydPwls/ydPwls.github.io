## 4. Git

Git은 **코드의 변경 내용과 이력을 관리하는 버전 관리 도구**임.

파일의 변경사항은 다음과 같은 영역을 거쳐 관리됨.

**작업 디렉토리 → 스테이징 영역 → 저장소**

수정한 파일은 바로 저장되는 것이 아니라 `git add`를 통해 스테이징 영역에 올리고, `git commit`을 통해 하나의 변경 이력으로 저장함.

### 주요 명령어

`git status`

현재 변경된 파일과 스테이징 상태를 확인할 수 있음.

`git diff`

아직 스테이징되지 않은 변경 내용을 비교할 수 있음.

`git log`

Commit 이력을 확인할 수 있음.

### Commit 되돌리기

이미 Push하여 팀원들과 공유된 Commit을 취소할 때는 `revert`를 사용할 수 있음.

아직 로컬에만 존재하는 Commit을 되돌릴 때는 상황에 따라 `reset`을 사용할 수 있음.

### Stash

작업 중인 변경사항을 아직 Commit하기 어려운 경우 `stash`를 이용해 임시로 보관한 뒤 다른 Branch로 이동할 수 있음.

## 5. GitHub

GitHub는 **Git으로 관리한 코드와 변경 기록을 인터넷의 원격 저장소에 올려 팀원들과 공유하고 협업할 수 있도록 하는 서비스**임.

GitHub에 있는 프로젝트를 처음 받아올 때는 Clone을 사용하며, 이후에는 Pull을 통해 원격 저장소의 최신 내용을 받아올 수 있음.

### 기본적인 협업 과정

**최신 코드 받기 → 새 Branch 생성 → 코드 작성 → Commit → Push → Pull Request 생성 → 검토 → Merge**

### Push

Push는 로컬의 Commit을 원격 저장소에 올리는 기능임.

### Fetch

Fetch는 원격 저장소의 최신 내용을 받아오지만 현재 Branch에 바로 반영하지 않는 기능임.

### Pull

Pull은 원격 저장소의 최신 내용을 받아와 현재 Branch에 반영하는 기능임.

### Pull Request

Pull Request(PR)를 이용하면 작업한 내용을 `main`에 바로 합치지 않고 팀원에게 검토를 요청할 수 있음.

검토 후 승인되면 Merge하여 변경사항을 반영할 수 있음.

### Conflict

여러 사람이 같은 부분을 수정하면 **Conflict(충돌)** 가 발생할 수 있음.

충돌이 발생하면 충돌된 내용을 직접 확인하고 수정한 뒤 다시 Commit하여 병합을 완료해야 함.

## 6. .gitignore

`.gitignore`는 **Git이 추적하지 말아야 할 파일이나 폴더를 지정하는 파일**임.

주로 다음과 같은 파일이 GitHub에 올라가는 것을 방지하기 위해 사용함.

- 빌드 결과물
- 개인 설정 파일
- 민감한 정보가 포함된 파일

프로젝트에서 관리할 필요가 없거나 GitHub에 공개되면 안 되는 파일을 `.gitignore`에 등록하여 Git의 추적 대상에서 제외할 수 있음.
