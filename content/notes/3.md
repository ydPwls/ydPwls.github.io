캡스톤 프로젝트 **챙김**의 프론트엔드 개발을 위해  
React 기초부터 Hooks, Form 처리까지 다시 복습함

이전에 학습했던 내용을 단순히 다시 보는 것보다  
실제 챙김의 기능에서 어떻게 활용할 수 있는지를 중심으로 정리함

## 10월 4일 - React 기초 복습

### Component

React에서는 화면을 여러 개의 **컴포넌트(Component)**로 나누어 구성할 수 있음

컴포넌트는 독립적인 UI 단위로, 화면을 기능별로 나누어 관리할 수 있고
필요한 경우 재사용할 수도 있음

챙김에서는 다음과 같이 화면을 나누어 구성할 수 있음

```text
챙김
├─ 상황 입력
├─ 질문
├─ 체크리스트
└─ 진행률
```

### Props

**Props**는 부모 컴포넌트에서 자식 컴포넌트로 데이터를 전달할 때 사용함

예를 들어 현재 선택된 이벤트를 체크리스트 컴포넌트에 전달하면
같은 컴포넌트에서도 이벤트에 따라 다른 내용을 표시할 수 있음

### State

**State**는 컴포넌트에서 변경되는 데이터를 관리할 때 사용함

챙김에서는 다음과 같은 값들이 State가 될 수 있음

```text
현재 이벤트
현재 질문
사용자가 입력한 값
체크리스트 완료 여부
진행률
```

State가 변경되면 React는 변경된 내용을 화면에 반영하기 위해
컴포넌트를 다시 렌더링함

간단한 상태는 `useState`로 관리하고,
여러 컴포넌트에서 함께 사용해야 하는 상태는 Zustand를 활용하는 방향을 고려하고 있음

### 챙김에 적용

사용자가 이벤트를 선택하면 해당 값을 State에 저장하고,
Props를 통해 다른 컴포넌트에 전달하는 구조로 활용할 수 있음

```text
이벤트 선택
    ↓
State 변경
    ↓
리렌더링
    ↓
Props로 이벤트 전달
    ↓
이벤트에 맞는 UI 표시
```

## 10월 5일 - React Hooks

React의 함수형 컴포넌트에서 상태 관리 등의 기능을 사용할 수 있도록 해주는
**Hooks**를 다시 복습함

이번에는 `useState`와 `useEffect`를 중심으로 학습함

### useState

`useState`는 컴포넌트에서 변경되는 상태를 관리하기 위한 Hook임

```jsx
const [event, setEvent] = useState("이사");
```

여기서 각각의 역할은 다음과 같음

```text
event
→ 현재 상태값

setEvent
→ 상태를 변경하는 함수

"이사"
→ 초기값
```

챙김에서는 현재 이벤트, 질문 단계, 입력값,
체크리스트 완료 여부 등을 관리하는 데 활용할 수 있음

### useEffect

`useEffect`는 컴포넌트가 렌더링된 이후
특정 작업을 실행할 때 사용할 수 있는 Hook임

```jsx
useEffect(() => {
  loadChecklists();
}, []);
```

빈 의존성 배열 `[]`을 사용하면
컴포넌트가 화면에 나타난 이후 Effect가 실행됨

따라서 체크리스트 화면에 들어왔을 때
서버에서 데이터를 가져오는 것과 같은 작업에 활용할 수 있음

```text
체크리스트 화면 표시
        ↓
useEffect 실행
        ↓
서버에 데이터 요청
        ↓
데이터 응답
        ↓
State에 저장
        ↓
리렌더링
        ↓
체크리스트 표시
```

### 챙김에 적용

챙김에서는 `useState`를 통해 화면에서 변경되는 상태를 관리하고,
`useEffect`를 이용해 화면이 나타난 후 필요한 데이터를 가져오는 방식으로 활용할 수 있음

이전에 학습했던 REST API 연동과 연결하면
서버에서 받아온 체크리스트 데이터를 State에 저장하고 화면에 표시할 수 있음

## 10월 6일 - React Form

챙김에서 사용자가 자신의 상황을 입력하는 기능을 구현하기 위해
React의 **Form 처리 방식**을 복습함

### Form

Form은 사용자로부터 데이터를 입력받기 위해 사용함

챙김에서는 사용자가 이벤트를 선택하고
자신의 상황을 자연어로 입력하는 부분에 활용할 수 있음

```text
이벤트 선택
→ 이사 / 취업 / 자동차 구매

상황 입력
→ 다음 달에 대구로 독립할 예정이에요
```

### onSubmit

`onSubmit`은 사용자가 Form을 제출했을 때 발생하는 이벤트를 처리함

```jsx
<form onSubmit={(e) => {
  // 입력값 처리
}}>
```

사용자가 입력을 완료하고 제출하면
입력된 이벤트와 상황을 가져와 이후 작업에 사용할 수 있음

### preventDefault

HTML Form은 기본적으로 제출하면 페이지가 새로고침됨

React에서 입력값을 직접 처리하기 위해 다음과 같이
`preventDefault()`를 사용할 수 있음

```jsx
e.preventDefault();
```

이를 통해 페이지 새로고침을 막고
현재 화면에서 입력값을 처리할 수 있음

### 챙김에 적용

챙김의 상황 입력 기능은 다음과 같은 흐름으로 구현할 수 있음

```text
사용자 이벤트 선택
        ↓
상황 입력
        ↓
Form 제출
        ↓
onSubmit 실행
        ↓
입력값 가져오기
        ↓
서버로 전달
        ↓
조건 추출 및 처리
        ↓
체크리스트 생성
```

간단한 입력은 `useState`로 관리할 수 있지만,
질문과 입력값이 많아지면 이전에 학습한 **React Hook Form**을 활용하여
입력값과 유효성 검사를 관리할 수 있음

3일 동안 새로운 기능을 많이 학습하기보다는
기존에 공부했던 React의 기본 개념을 챙김의 실제 개발 흐름과 연결하여 복습함

이번 학습 내용을 챙김에 연결하면 전체적인 프론트엔드 흐름은 다음과 같음

```text
사용자 상황 입력
      ↓
Form 처리
      ↓
State 관리
      ↓
REST API 요청
      ↓
서버에서 데이터 처리
      ↓
체크리스트 응답
      ↓
State에 저장
      ↓
React 리렌더링
      ↓
체크리스트 UI 표시
```

앞으로는 지금까지 학습한 내용을 바탕으로
상황 입력과 체크리스트 UI를 실제 프로젝트 구조에 적용할 예정임
